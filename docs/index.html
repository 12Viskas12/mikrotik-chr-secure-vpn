How the secure CHR + VPN network works

Below is a diagram of the lab and four stories about what happens to packets: what is allowed, what is blocked, and what happens when the VPN goes down. Press "Next" and watch the packet travel.

Local networkAn office with a locked door. Only staff get in; strangers stay out.
CHRA guard at the only entrance. Checks everyone against a list and logs every refusal.
WireGuardAn armoured tunnel to the branch office. Nobody outside can see what travels inside.
ServerA safe in the branch. It opens for one key only, through two doors: SSH and HTTPS.
Fail closedIf the tunnel is closed, the guard does not let anyone go "round by the street". The door is simply locked.

What it is made of

In the lab everything is a virtual machine on one computer. Later the "remote side" becomes your real server.

Your computer

Arch · QEMU/KVM

Runs all VMs, joins them with virtual cables (bridges) and gives the CHR Internet access. Deliberately not connected to the client network.

MikroTik CHR

router in a VM

The only door between clients, the Internet and the VPN. All rules live here: what to allow, what to block, what to log.

Remote side

VMs rgw + rsrv

A gateway with WireGuard and a server with SSH and HTTPS. They imitate your future real server and enforce the same restrictions.

Clients

client1, client2

Ordinary users of the isolated network. The tests run from them: server access, denials, failure when the VPN is down.

Five layers of protection

If one layer fails, the next one still holds.

1. Host bridgeFrames from unknown devices never reach the client network. Each port is pinned to its MAC. Clients cannot talk to each other directly.
2. HostThe host has no address in the client network. It forwards only Internet traffic, so the CHR cannot be bypassed through it.
3. CHREverything is denied by default. Only the listed clients, one server and two ports are allowed. Spoofed addresses are dropped at the entrance, refusals are logged.
4. WireGuardEncryption and keys. The peer is allowed only two addresses: the gateway and the server. Nothing else passes through the tunnel.
5. Gateway rgwA second check at the other end of the tunnel: the same single server and the same ports.

Terms you will meet

Bridge
A virtual switch in Linux. The virtual cables of the VMs plug into it.
TAP
A virtual "plug" for one VM: one end in the bridge, the other in the VM network card.
NAT
Replaces the sender address with the exit address. This is how internal addresses reach the Internet.
WireGuard
A modern VPN: an encrypted tunnel between two nodes, authenticated by keys.
Fail closed
When protection breaks, the system closes instead of opening. No VPN means no access.
Netwatch
A CHR feature that pings the gateway every 5 seconds and enables or disables the route.
Blackhole
A route that simply discards packets. It keeps traffic from leaving around the VPN.
Anti-spoofing
Protection against forged sender addresses: "I am 10.50.0.10" is accepted only from the real LAN.

What you do by hand

./lab.sh upBuilds the whole network and starts the VMs with the VPN. The first run downloads images.
./lab.sh statusWhich VMs are running, whether the tunnel is alive, whether the route to the server is enabled.
./lab.sh testThe 10 required checks and a report in reports/test-results.md.
./lab.sh shell client1 '...'A command inside a client. The host has no access to the LAN, hence this way.
ssh admin@172.31.0.2CHR administration. Accepted from the host only.
./lab.sh backupExports the CHR configuration without secrets to docs/.
./lab.sh downRemoves the VMs, bridges and rules from your computer.
